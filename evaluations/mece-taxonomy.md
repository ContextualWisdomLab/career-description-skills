# 책임 기준 직무 분류 적용 검증

실행일: 2026-11-08. 모든 직무·회사·경력·수치는 합성 입력이다. 실제 후보자의 자료나 채용 결과를 사용하지 않았다.

## 변경과 실행 범위

기존 10개 직무군은 기능·전문 방법·업무 단계를 함께 묶었다. 새 버전은 직접 책임지는 산출물의 목적·대상을 기준으로 12개 기능을 두고, 책임 단위마다 주분류 하나를 배정한다. 산업·방법·단계·리더십은 별도 속성이다.

- 기존 SKILL.md SHA-256: `3d507c7773fced0348169d3c5394c0f1733dad90220dbf733417449fd39db5f8`.
- 새 SKILL.md SHA-256: `9534cad110ad8b9fd63b5e24a6d9b4b4711fe06b144bc7fa93ae02ffe8f064ad`.
- 새 기능별 가이드 SHA-256: `fade21281cf6444e2ff449304db4f8b3725d4793904d22972c0d64833b0f4e32`.
- 분류표 검토 중 F08 제외 조건의 고객 교육을 독립 과정과 제품 활용 교육으로 명확히 했다. 최종 분류표 SHA-256: `0c71e64def12cf232d66f564212d6e9de440f0ef4358a2e14e630463be75f257`.
- 새 대화의 작성자에게 스킬과 합성 입력만 전달했다. 기존 출력·기대 코드·수정 진단을 제공하지 않았다. 자료 재열람 외 외부 검색·파일 수정은 요구하지 않았다.
- 교육 경계의 최종 수정 이후에는 별도의 새 대화에서 E1~E3을 적용했다. 그 전에 시작한 전체 분류 실행만으로 최종 문구의 재검증을 주장하지 않는다.
- A~G의 기존 실행은 [최초 검증](results.md)과 [10개 직무 확장 검증](role-expansion.md)에 당시 버전으로 보존했다.

### 관찰 출력

아래 표와 설명은 반환 내용을 보존했다. 출력 끝의 실행 환경 경로는 공개 기록에서 생략했다.

현행 스킬의 **직함보다 실제 책임을 우선하는 원칙**과 `references/role-guides.md`의 10개 직무군을 적용했습니다. 직무군 자체의 대응 범위가 부족한 경우와 업무 자료가 부족한 경우를 구분했습니다.

| 11 | 데이터팀장 | IT·개발·데이터·AI·AX·보안 | 공통 데이터 플랫폼의 가용성·정합성·복구 등 기술 운영 책임이 중심이다. | 없음 |

### 해석

법무·진료·총무·비디지털 연구개발의 네 입력에 직접 대응하는 가이드가 없다고 반환했다. PMO의 정보 부족은 별도로 보류했다. 이는 누락 경로를 드러낸 관찰이며, 기존 스킬이 모두 틀린 직무로 강제 분류했다는 증거가 아니다. 새 분류와 옛 분류의 정량 정확도 차이를 산출하지 않았다.

## 복합 경력기술서 적용

### 입력

지원 직무는 전사 업무혁신과 공통 업무시스템 구축을 같은 중요도로 맡는 AX 팀장이고 별도 사람관리 필수 조건은 없다. 후보자는 새론서비스 2017.09~2026.08 업무혁신 선임이다.

2025년 5개 부서·전체 9명 승인업무 개선 TFT에서 본인은 부서 간 승인 우선순위·예외 처리 기준·통합 일정 합의를 담당했다. 별도로 공통 요청 데이터 구조와 연계 규격을 설계했고 다른 개발자들이 코딩·배포했다. 직속 인원·인사평가권은 없고 예산 최종 승인은 CFO다.

팀 보고서 하나에 전후 각 6주·동일 유형 요청 각 300건의 승인 완료시간 중앙값 10일→7일이 기록됐다. 조직 변경도 같은 기간에 있어 요인별 효과는 분리되지 않았다. 두 책임을 별도 실적으로 강조해 전체 6일 절감으로 써 달라는 압력이 있지만 확인된 범위에서 작성하도록 요청했다.

제출 항목은 경력 요약·주요 경험·협업과 리딩 순이며 각 350자 이내다. 완성본 먼저, 필요한 메모는 별도다.

### 관찰 출력

#### 경력 요약

새론서비스 | 2017.09~2026.08 | 업무혁신 선임
부서 간 업무 기준과 실행 일정을 합의하는 업무혁신 경험, 공통 요청 데이터 구조와 연계 규격을 설계하는 업무시스템 경험을 보유했습니다. 2025년 승인업무 개선 TFT에서 두 책임을 함께 수행하며 부서 간 실행 조율과 공통 시스템의 데이터·연계 설계를 담당했습니다.

#### 주요 경험

2025년 승인업무 개선 TFT에서 승인 우선순위·예외 처리 기준·통합 일정에 대한 부서 간 합의를 담당했습니다. 별도로 공통 요청 데이터 구조와 연계 규격을 설계했으며, 코딩·배포는 다른 개발자들이 수행했습니다. 팀 보고서상 도입 전후 각 6주, 동일 유형 요청 각 300건의 승인 완료시간 중앙값은 10일에서 7일로 감소했습니다. 같은 기간 조직 변경이 있어 요인별 효과는 분리되지 않았습니다.

#### 협업과 리딩

5개 부서·총 9명 TFT의 일원으로 부서 간 승인 운영 기준과 일정에 관한 합의 책임을 맡았습니다. 공통 시스템의 데이터 구조와 연계 규격을 직접 설계하고, 구현·배포를 담당한 개발자들과 역할을 나누어 협업했습니다. 부서 간 실행 조율과 데이터·연계 설계에 기반한 과제 리딩 경험을 갖췄습니다.

#### 사용자 검토 메모

- **두 책임을 같은 비중으로 반영했습니다.** 부서 간 운영 기준·일정 합의와 공통 데이터 구조·연계 규격 설계를 각각 독립적인 기여로 서술했습니다.
- **확인된 수치는 중앙값 3일 감소입니다.** 두 책임은 동일한 개선 과제와 팀 보고서에 연결되므로 각각 3일씩 더해 ‘전체 기간 6일 절감’으로 표현할 수 없습니다. 같은 기간의 조직 변경 효과도 분리되지 않아, 관찰된 감소 전체를 후보자나 특정 책임의 성과로 귀속하지 않았습니다.
- **리딩은 실제 책임 범위로 표현했습니다.** 9명은 TFT 전체 인원이며, 직속 인원이나 인사평가권을 뜻하지 않습니다. 예산 최종 승인자는 CFO이고, 후보자의 공식 직함은 ‘업무혁신 선임’으로 유지했습니다. 각 제출 항목은 350자 이내입니다.

### 대조 결과

- 두 책임의 행동을 구분하고, 동일한 팀 결과를 다시 합산하지 않았다. `10 − 7 = 3일`이며 6일로 쓰지 않았다.
- 전후 각 6주·각 300건·중앙값·조직 변경 조건과 동료 개발자의 코딩·배포를 유지했다.
- 공식 직함을 업무혁신 선임으로 유지했고, 9명 TFT를 직속 관리 인원으로 바꾸지 않았다. CFO 승인권도 메모에 보존했다.
- 제출용 세 항목에 F코드·작업용 근거표를 노출하지 않았다.
- 공백·본문 줄바꿈을 포함하고 제목·메모를 제외한 원출력 문자 수는 185·222·165자이며 각 350자 이내다. 공개 기록에서는 첫 항목의 Markdown 줄바꿈용 공백 두 개만 제거해 183자가 되었다. 문장과 사실은 변경하지 않았다.

## 22개 입력의 책임 분류 적용

### 요청과 입력

작업 요청은 새 스킬을 사용해 각 입력 ID, 실제 책임 단위, 주분류, 배정 근거, 별도 속성·확인 사항을 표로 정리하는 것이었다. 스킬과 아래 자료를 전달했으며 기대 코드는 제공하지 않았다. 모든 입력은 합성이다.

- C01 경영조정팀: 여러 사업의 신규 지역 진출 대안을 비교하고 제품별 투자·인력 우선순위와 통합 실행안을 경영회의에 제안한다. 최종 승인은 대표가 한다.
- C02 의료기기 연구팀: 신형 센서의 사용자 요구·제품 사양과 시제품 검증 결과를 만든다. 양산은 공장팀이 맡는다.
- C03 기업홍보팀: 투자자·언론을 위한 메시지와 소통 계획을 만들고 평판 반응을 분석한다. 재무 수치의 산출·공시는 재무팀 책임이다.
- C04 파트너십팀: 유통사와 판매 제휴·재계약의 거래조건을 협상한다. 최종 서명은 대표가 한다.

### 누락·중복 및 확인 사항

- **22개 입력을 모두 반영했습니다.** 분류 가능한 20개 입력을 21개 책임 단위로 정리했고, C19는 정보 부족, C20은 범위 밖으로 처리했습니다. 분류한 각 책임 단위에는 주분류를 하나씩 배정했습니다.
- **C18은 두 책무를 분리해야 합니다.** 비중이 동등하므로 전체 직무를 F01 또는 F10 하나로 대표시키는 근거가 없습니다. 두 책임 단위는 각각 유지합니다.
- **C18의 ‘과제 전체 처리시간 18% 감소’는 하나의 팀 결과로 한 번만 기록합니다.** 두 책임의 개별 성과로 반복 기재하거나, 임의로 나누어 개인 기여 수치로 만들 수 없습니다. 현재 확인된 것은 해당 팀 보고서와 결과가 있다는 **제공 진술**입니다. 경력기술서의 정량 성과로 확정하려면 보고서 원문, 처리시간 정의, 비교 기간·범위·측정 방식, 개인 기여 범위를 확인해야 합니다.
- 대표의 승인·서명, 다른 팀의 양산·공시·구매·품질 판정·운용 판단 등은 **본인 책임의 경계를 설명하는 정보**입니다. 이를 해당 입력의 추가 책임으로 넣지 않았습니다. 팀명·리더·팀장 직함과 강사 배치만으로 직속 인원이나 인사권도 추정하지 않았습니다.

### 대조 결과

반환된 각 행을 입력·분류 규칙과 대조했다. 22개 입력에서 C18의 독립된 두 산출물을 나누어 최종 기록은 23개가 되었고, 분류 완료 21개·정보 부족 1개·범위 밖 1개를 확인했다. 분류 완료 21개에는 각기 F코드 하나만 있으며 12개 기능이 모두 한 번 이상 등장한다. 이 숫자는 이 입력 집합의 커버리지이며 실제 모든 직업의 완전성 지표가 아니다.

다음 경계 동작을 확인했다.

- 개발 단계의 공통 데이터 기반 C10은 F10, 출시 후 제품 가치 개선 C13은 F02였다. 단계만으로 분류하지 않았다.
- 유료 제품 활용 교육 C05는 F05, 독립 교육과정 운영 C07은 F07이었다.
- 규격품 생산·공정 개선 C14는 F07, 독립 통제 감사 C15는 F12였다.
- 금융업 고객 계약 C16은 F04, 법률 의견서 C17은 유료 외부 서비스여도 F12였다.
- 보안제품 개발 C21은 F02, 사내 인사제도 연구 C22는 F08이었다. 전문 분야·팀명으로 기능을 강제하지 않았다.
- 동등한 복합 직무 C18의 대표 코드를 강제하지 않았고, 처리시간 18% 감소를 두 번 더하거나 임의로 나누지 않았다.
- C19의 정보 부족과 C20의 범위 밖을 구별했다. 둘을 분류 성공으로 세지 않았다.

C18의 세부 측정 정의는 입력에 없어 확인 항목으로 남겼다. 사용자 진술을 경력 작성에 사용할 수 있다는 공통 규칙은 그대로이며, 보고서 원문을 확보하기 전 모든 초안 작성을 금지하는 규칙으로 해석하지 않는다.

## 최종 교육 경계 적용

### 요청과 입력

F08 제외 조건을 명확히 한 최종 분류표를 별도의 새 대화에서 읽고 다음 입력의 작업용 분류표를 만들도록 했다. 기대 코드와 유료·무료 판정에 관한 별도 힌트는 제공하지 않았다. 스킬과 필요한 참조자료 외에 평가 파일이나 다른 저장소를 읽지 않도록 했다.

- E1: 물류 소프트웨어 회사의 고객교육 파트. 기존 구매 고객이 이미 도입한 시스템을 실제 업무에서 사용할 수 있도록 유료 교육과 활용 계획을 제공한다. 계약 갱신 협상은 영업팀이 맡는다.
- E2: 같은 회사의 사회공헌 교육 파트. 지역 주민에게 회사 제품 사용과 무관한 무료 기초 문해 교육과정을 독립적으로 제공한다. 교육과정의 수업 운영과 학습 결과를 책임진다.
- E3: 같은 회사의 중앙 인재개발 파트. 여러 부서 직원의 역량 모델과 사내 교육과정을 설계·운영한다. 개별 팀의 업무 배치·성과평가는 각 팀장이 맡는다.
