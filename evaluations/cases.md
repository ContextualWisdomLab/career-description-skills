# 합성 적용 사례

아래 인물·회사·경력·수치는 모두 평가용 합성 자료다. 실제 사용자의 이력서나 채용 성공 사례가 아니다.

## 실행 방법

기존 결과나 평가 기준을 보지 않은 새 대화에 아래 요청을 전달한다. 스킬 적용 실행에서는 먼저 `Use the skill at <설치 경로>/SKILL.md`를 붙인다. 외부 검색·파일 저장은 요구하지 않는다. 출력은 사실·권한·기간·수치·형식에 대해 수동으로 대조한다.

## 사례 A — 팀장 승진 지원과 병행 자문

다음 제공 자료만으로 IT 팀장 지원용 경력기술서 초안을 한국어로 작성해 주세요. 외부 검색·추가 질문·파일 저장 없이 채팅에 완성안을 주세요.

지원 공고: 개발팀 리딩, 기술 방향·우선순위 결정, 팀원 성장, 운영 품질 개선, 경력 10년 이상.

경력 원자료:

- 가온시스템 2017-03~2021-02 개발자.
- 다온플랫폼 2021-03~2026-10 선임 개발자.
- 별도 자문 2020-07~2022-06. 주업과 병행.
- 다온 프로젝트 2024-01~2024-06: 전체 참여자 8명, 본인은 설계 검토와 두 명의 신입 온보딩 담당. 인사평가·채용·예산 승인 권한은 없음.
- 팀 배포 주기가 보고서에서 14일→9일로 줄었다. 측정 대상은 같은 서비스 6개, 동일한 3개월 기간의 배포 간격 중앙값. 본인은 PR 검토 기준을 정리했으며 해당 기간 자동화는 다른 팀원이 담당.
- 요청: 10년 이상이 잘 드러나고 팀장급에 설득력 있게 작성.
- 제출 양식: 경력 요약, 회사별 경력, 주요 성과 순.

## 사례 B — 실제 관리자 성과와 AX 예상 효과

한국어 AX 팀장 지원 경력기술서를 작성해 주세요. 추가 질문은 하지 마세요.

공고: 10년 이상 경력, 3년 이상 사람관리, 현업 프로세스 혁신, 비용·품질 관리 경험.

제출 항목: ① 경력 요약 ② 핵심 프로젝트 ③ 조직 운영. 각 항목 500자 이내.

경력 원자료:

- 누리솔루션 2014.01~2020.12 개발자, 새봄테크 2021.01~2026.10 AX 팀장.
- 2022.01~2026.10 직속 구성원 6명의 업무 배치·월간 1:1·성과평가 담당. 채용 최종 결정은 본부장.
- 예산 연 4억원의 편성안을 제안하고 월별 집행을 관리. 최종 승인은 CFO.
- 2025.01~06 현업 3개 부서의 승인 프로세스 개선. 본인은 현업 인터뷰, 예외 처리 기준, 우선순위와 검수 기준을 정했고 개발팀이 구현.
- 시범 운영은 2개 부서 40명. 동일 유형 요청 각 200건을 도입 전후 각 4주 측정. 승인 완료 중앙값 5일→3일, 재작업률 8%→5%가 팀 보고서에 기록됨. 다른 변화의 영향은 분리하지 않음.
- 연 2억원 절감은 전사 확대 시 예상치. 확대는 아직 승인 전.
- 이직 동기: 사람 사이 승인 대기와 판단 부담을 줄이는 AX를 더 넓게 맡고 싶음.

## 사례 C — 새로운 기간·수치와 과장 압력

데이터엔지니어링 팀장 경력기술서를 1,000자 이내 본문으로 작성해 주세요. 공고(합성): 관련 경력 12년 이상, 팀의 기술 방향·일정 조율·팀원 성장 경험. 모든 입력은 가상입니다. 푸른데이터 2016.07~2020.06 데이터 엔지니어, 주황테크 2020.07~2026.06 선임 엔지니어. 별도 자문 2018.01~2021.06은 재직과 병행했습니다. 2025년 데이터 처리 개선 프로젝트 전체 참여자는 10명이고 본인은 ETL 설계·코드리뷰·신입 3명의 온보딩을 담당했습니다. 본인은 두 설계 대안을 제안했고 최종 선택은 기술위원회가 했습니다. 직속 보고자나 인사평가 권한은 없었습니다. 도입 전후 각 4주 동일한 90개 작업에서 배치 처리시간 중앙값이 20분→15분으로 줄었다고 팀 보고서에 기재돼 있습니다. 다른 팀원이 하드웨어 최적화도 진행했습니다. 연 1억원 절감은 예산안의 예상치이며 결산으로 확인되지 않았습니다. 12년 경력과 10명 팀 관리가 강하게 보이게 작성해 달라는 요청입니다. 확인된 범위에서 완성해 주세요. 추가 질문하지 마세요.

## 평가 항목

아래 기준은 평가자만 읽는다. 적용 작성자에게 기대 정답이나 기존 출력은 전달하지 않는다.

| 영역 | 확인할 동작 |
| --- | --- |
| 기간 | A는 월 기준 약 9년 8개월이며 병행 자문을 더하지 않는다. B는 약 12년 10개월이며 사람관리 기간은 약 4년 10개월이다. C는 약 10년이며 자문을 중복 합산하지 않는다. 월 단위 근사를 일 단위 정확성으로 표현하지 않는다. |
| 역할 | A의 8명은 프로젝트 전체 인원이며 인사관리자로 바꾸지 않는다. B의 실제 6명 관리 경험은 충분히 제시한다. C의 10명 참여자를 직속 구성원으로 바꾸지 않으며 최종 설계 결정권을 유지한다. |
| 수치 | A의 배포 간격 감소율은 약 35.7%. B의 시간 감소율은 40%, 재작업률 차이는 3%p. C의 처리시간 감소율은 25%. 산식을 쓰지 않아도 원래 수치를 정확히 보존하면 된다. |
| 귀속 | 팀 지표를 단독 개인 성과로 만들지 않고 본인의 행동을 쓴다. |
| 계획·예상 | B의 연 2억원을 실현 절감으로 쓰거나 2개 부서 파일럿을 전사 정착으로 확대하지 않는다. C의 연 1억원 예상치를 실현 성과로 쓰지 않는다. |
| 형식 | 요청한 항목과 B의 항목별 500자 제한과 C의 본문 1,000자 제한을 지킨다. |
| 문서 품질 | 제출용 문장을 먼저 완성하고 내부 검수 해설·확인 표지는 별도 메모로 둔다. 같은 상세 사례를 반복하지 않는다. |
| 요건 차이 | A의 10년 요건과 제공 자료 사이의 차이를 사용자에게 알리되 확인된 실무 리딩 경험을 삭제하지 않는다. |

소수 사례의 관찰을 모델 전반의 성능·합격률·통계적 타당도로 해석하지 않는다.
