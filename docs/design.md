# 요구사항과 설계

## 목적

팀장급 채용 사례를 조사하고, 경력기술서를 작성·검토하는 재사용 스킬과 저장소를 만든다. 실제 책임과 판단, 본인의 행동, 팀 성과가 상세 경력에 드러나도록 하는 데 중점을 둔다.

## 범위

- 기업·기관의 사업 수행·조직 지원·보증 책임을 [12개 기능](../skills/write-career-description/references/job-taxonomy.md)으로 분류한다. 주분류는 직접 책임지는 산출물의 목적과 대상을 기준으로 정한다.
- 책임 단위마다 주분류 하나를 부여하고 산업·기술·AI·AX·단계·리더십을 별도 속성으로 기록한다. 복합 직무를 분리하고 같은 성과는 다시 합산하지 않는다.
- 국내외 공개 공고와 직무 자료를 조사한다. 기업의 원문, 공식 ATS, 채용 플랫폼에 실린 공고, 과거 자료를 구분하고 각각의 상태와 확인한 범위를 기록한다.
- 한국 테크 기업의 역할은 제품·개발뿐 아니라 영업·인사·고객 운영 등 해당 기능에 따라 비교한다. 기업·산업은 별도 속성으로 유지하며 12개 기능에 새로운 기업군 분류를 덧붙이지 않는다.
- 새로운 직무·전문 분야는 해당 역할의 목적·책임·판단·산출물·권한을 직접 조사하고 작성 기준을 보강한다. 이름이 낯설거나 자료집에 없다는 이유로 미확정 상태나 분류 범위 밖에 두지 않는다.
- 공고의 필수·우대 요건, 담당 업무, 작성 지침을 구별하고 후보자의 경력 근거와 연결한다.
- 경력 기간의 중복, 실제 권한, 성과 수치와 제출 형식을 검수한다.
- 사람관리 경험이 없는 직무 전문 리드의 경험도 정확하게 작성한다. 직함으로 인사권을 추정하지 않는다.
- 정기 결산·영업 실적·채용·생산·서비스 운영을 해당 업무의 단위로 설명하며, 직무별 지표 정의와 실제 기여를 보존한다.
- 경력기술서 초안을 우선 완성하고 확인 사항은 별도로 전달한다.
- 업무의 필요성, 방법·순서·기준을 택한 이유, 본인의 행동, 결과의 의미를 근거와 함께 연결한다. 직무 조사로 개인의 실제 선택 이유를 대신 만들지 않는다.

실제 후보자의 지원서 작성이나 자동 제출, 채용 결과 예측은 이번 배포 작업의 범위에 포함하지 않는다.

## 설계 선택

1. **단일 스킬과 필요한 참조자료**를 선택했다. 조사·작성·검토를 하나의 스킬에서 수행해 요건과 경력의 연결을 유지한다.
2. **고정 서식보다 조건에 따른 구성**을 선택했다. 지정 양식이 우선이며 자유 양식은 참고 구조를 제공한다.
3. **실행 코드 없는 초기 버전**을 선택했다. 일반적인 도구로 할 수 있는 날짜·비율 계산을 별도 프로그램으로 다시 구현하지 않는다.
4. **korean-editing을 적용해 한국어를 편집**하도록 했다. 설치본이 없으면 공식 저장소의 지침을 읽고 적용한다. 한국어 문법 규칙을 이 저장소에 복제하지 않는다.
5. **공개 출처의 링크·자체 요약과 합성 사례**만 저장한다. 실제 후보자 자료는 재사용 스킬에 넣지 않는다.
6. **책임 분류와 기능별 작성 가이드를 구분**한다. 포함·제외 조건으로 먼저 분류하고 필요한 F코드의 질문·지표만 읽는다. 공통 수치·권한 규칙은 하나로 유지한다.
7. **정보가 부족하거나 분류 범위를 벗어났으면 그 상태를 기록한다.** 대표 기능이 불명확한 복합 직무는 책임별 배정을 유지하고 대표 코드만 확인 전으로 둔다. 분류 체계가 다루는 기능의 범위와 실제 채용 사례를 조사한 범위를 구분한다.
8. **직무 조사가 부족한 경우와 후보자의 사실을 확인하지 못한 경우를 구분한다.** 전자는 작성자가 조사해 보강하고, 후자는 후보자의 자료와 진술을 확인한다. 실제 지원 공고가 없거나 새로운 전문 분야를 다룰 때도 직무를 조사한다.
9. **독자의 ‘왜?’에 답하는지 내용 검수에 포함한다.** 근거 없는 동기나 위기를 추가하지 않으면서 일의 필요성, 선택 기준, 결과의 사용처가 드러나도록 연결한다. 문장마다 같은 틀을 반복하지 않는다.
10. **한국 기업의 공고와 현업자의 작성 경험을 구분한다.** 공고에 나온 팀의 성장 단계·책임·제출 요구는 해당 회사의 조건으로 기록한다. 과거 기술블로그의 개인 작성 경험은 서술할 때 참고하되, 현재 채용 정책이나 합격 효과로 바꾸지 않는다.

이 설계는 사용자가 요청한 범위를 구현하기 위해 작성자가 선택한 것이다. 특정 기관이 채택하거나 검증한 표준은 아니다.

## 완료 기준

- 출처별 원문·날짜·확인 범위와 적용 한계가 기록되어 있다.
- 유효한 SKILL.md, UI 메타데이터, 필요한 참조자료와 문서 구성안이 있다.
- 경력 중복, 권한 과장, 팀 지표, 예상 효과, 지정 양식 조건을 합성 입력으로 점검한다.
- 직무를 확장하면서 보강한 계약·매출·수금, 공정 범위, 예산·실적, 수치 없는 운영 개선의 작성 기준을 각각의 합성 사례에 적용한다.
- 경계가 겹치는 사례, 복합 책임, 정보가 부족하거나 분류 범위를 벗어난 사례에 분류 규칙을 적용한다. 동일한 성과를 중복 합산하거나 분류 코드를 제출본에 넣지 않는지 점검한다.
- 새로 보강한 13개 역할의 원문·날짜·열람 범위와 직무별 작성 질문을 기록한다.
- 추가 자료집에 있는 직무와 없는 직무에 각각 스킬을 적용한다. 실제로 직무를 조사했는지, 선택 이유와 성과에 관한 사실을 보존했는지 확인한다.
- 한국 테크 기업 사례의 정확한 역할·국내 소속·날짜·열람 범위와 작성 질문을 연결한다. 기업별 제출 조건과 실제 인사관리 범위를 합성 경력 작성에 적용한다.
- 구조 검증과 상대 링크 확인을 통과한다.
- 개인 스킬 설치 결과를 원격에서 확인한다.
- 저장소 커밋과 게시 여부를 각각 검증한다.

## 검증의 한계

소수의 합성 사례에 적용한 결과는 해당 입력에서 관찰한 동작을 보여 준다. 채용 성과, 모든 문서 형식, 특정 ATS 또는 실제 후보자의 사실관계를 검증한 결과로 확대하지 않는다. 평가 기록에 실행하지 않은 검사를 성공했다고 적지 않는다.

분류 규칙은 명시한 범위 안에서 입력된 책임을 중복 없이 배정하고 누락을 드러내도록 설계했다. 모든 산업과 직업을 수학적으로 완전하게 포괄한다거나 공식 직업분류 인증을 받았다고 주장하지 않는다. 기존 A~G 실행은 당시 버전의 기록으로 보존한다.

## 한국어 편집 기준

2026-11-08 편집에는 [korean-writing-skills의 korean-editing](https://github.com/ContextualWisdomLab/korean-writing-skills/blob/70b3a9ced7a102c2bda73d0d8ea3b7dd33c152c2/skills/korean-editing/SKILL.md)을 적용했다. 문장 수리, 문단 퇴고, 이력서·경력기술서, 업무 보고서의 지침을 문서의 목적에 맞게 사용했다. 이는 해당 스킬의 편집 절차를 적용한 것이며, 모든 수정이 어문 규정에 따른 오류 교정이라는 뜻은 아니다.

검토 범위는 스킬 본문·참조자료·구성안·UI 문구와 저장소의 안내·설계·평가 문서에 있는 한국어다. 명사를 나열해 관계가 불분명했던 표현은 행동과 대상이 드러나도록 고치고, 긴 문장은 조건과 예외를 보존하며 나눴다. 자연스러운 문구는 유지했다.

출처의 직접 인용, 공식 직무명, 과거 평가의 실제 입력·응답은 당시 기록으로 보존한다. 평가 문서에서는 설명과 판정 문장을 편집하며, 이전의 실패·제한을 새 실행의 성공으로 바꾸지 않는다. 수치·날짜·단위·출처·책임 범위·의무 수준은 수정 전후를 대조한다.

이번에는 한국어가 있는 22개 파일을 검토하고 21개 파일을 수정했다. 자연스러운 UI 문구는 유지했다. 스킬 형식 검사와 상대 링크 77개 확인을 통과했고, 설치본과 공개본의 작성 파일 12개를 대조했다. 12개 기능과 채용·직무 사례 34건, 별도 작성 사례 KW01을 유지했다. 기존 출처 URL·공식 직무명·사례 번호·수치와 과거 평가의 입력·응답 14개 구간, 직접 인용 2개가 보존되었는지 확인했다. 문맥을 읽으며 책임·조건·인과·의무 수준도 대조했다.

### 편집 후 합성 경력에 적용

기존 대화 맥락을 받지 않은 작성자에게 현재 스킬, 위 버전의 korean-editing 지침과 다음 합성 자료를 전달했다. 주요 경험 한 절을 400자 이내로 작성하고 필요한 메모는 본문 뒤에 두도록 요청했다. 기대 문장이나 다른 평가 기록은 제공하지 않았다. 적용 당시 SKILL.md의 SHA-256은 `e82dd94bd632709b2d192b87e8b5f8830a6097f4991a2b0f02ce740aa2281d07`이다.

**제공한 사실:** 목표 역할은 월별 결산 자료 취합·검토와 부서 협업을 맡는 재무·회계 팀장이다. 별도 인사관리 요건은 없다. 후보자의 공식 직함은 회계 선임이며, 2025.01~06의 취합 개선을 담당했다. 부서별 제출 항목이 달라 자료가 빠지는 일이 반복되어 공통 확인표를 제안했다. 시스템 교체는 승인되지 않았다. 팀장이 승인한 범위에서 엑셀 확인표를 설계·배포하고 매주 누락 항목을 확인했다. 협업자는 6명이며 직속 인사권은 없다. 같은 4개 부서에서 1월 결산 때 누락 18건, 6월 결산 때 7건을 기록했다. 3월에는 부서 담당자도 교체되었다. 결산 기간 단축이나 비용 절감 자료는 없다.

**관찰한 응답:** 아래에는 제목·본문·메모를 그대로 보존했다. 작성자는 별도로 스킬 본문, 분류표, 기능 가이드, 제출 검수와 한국어 편집의 문장 수리·경력 문서 지침을 읽었다고 보고했다.

```text
### 결산 자료 취합 개선 | 회계 선임 | 2025.01~06

부서별 제출 항목이 달라 자료 누락이 반복되어 공통 확인표를 제안했습니다. 시스템 교체가 승인되지 않은 상황에서 팀장이 승인한 범위에 따라 엑셀 확인표를 설계·배포했습니다. 6명과 협업하며 매주 누락 항목을 확인했습니다. 같은 4개 부서의 결산 자료 누락은 1월 18건에서 6월 7건으로 줄었습니다.

메모: 3월 부서 담당자 교체도 있어, 누락 감소를 확인표 도입만의 효과로 단정하지 않았습니다.
```

**대조 결과:** 제목·메모를 제외한 본문은 공백과 문장부호를 포함해 167자로, 400자 제한을 지켰다. 개선의 필요성, 시스템 교체가 승인되지 않은 상황과 선택한 방법, 본인의 설계·배포·점검이 연결되었다. 회계 선임이라는 직함과 팀장의 승인권, 협업 인원, 동일 부서의 1월·6월 비교를 유지했다. 담당자 교체는 별도 메모에 남겼으며, 비용 절감이나 결산 기간 단축을 추가하지 않았다. 이 한 사례의 관찰을 모든 직무에 대한 검증이나 과거 평가의 재실행으로 확대하지 않는다.
