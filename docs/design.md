# 요구사항과 설계

## 목적

팀장급 채용 사례를 조사하고, 경력기술서를 작성·검토하는 재사용 스킬과 저장소를 만든다. 상세 경력에서 실제 책임과 판단, 개인 행동, 팀 성과를 설명하는 것이 중심이다.

## 범위

- 기업·기관의 사업 수행·조직 지원·보증 책임을 [12개 기능](../skills/write-career-description/references/job-taxonomy.md)으로 분류한다. 주분류의 축은 직접 책임지는 산출물의 목적·대상이다.
- 책임 단위마다 주분류 하나를 부여하고 산업·기술·AI·AX·단계·리더십을 별도 속성으로 기록한다. 복합 직무를 분리하고 같은 성과는 다시 합산하지 않는다.
- 국내외 공개 공고·직무 자료를 조사하고, 기업 원문·공식 ATS·플랫폼 게재·과거 자료의 확인 수준과 상태를 구분한다.
- 한국 테크 기업의 역할을 제품·개발뿐 아니라 영업·인사·고객 운영 등 해당 기능으로 비교한다. 기업·산업은 별도 속성으로 유지하며 12개 기능에 새로운 기업군 분류를 덧붙이지 않는다.
- 새로운 직무·전문 분야는 해당 역할의 목적·책임·판단·산출물·권한을 직접 조사하고 작성 기준을 보강한다. 낯선 이름이나 자료집의 부재를 미확정·범위 밖의 근거로 쓰지 않는다.
- 공고의 필수·우대·업무·작성 지침을 구별하고 후보자 근거와 연결한다.
- 경력 중복·권한·성과 수치·제출 형식을 검수한다.
- 사람관리 경험이 없는 직무 전문 리드의 경험도 정확하게 작성한다. 직함으로 인사권을 추정하지 않는다.
- 정기 결산·영업 실적·채용·생산·서비스 운영을 해당 업무의 단위로 설명하며, 직무별 지표 정의와 실제 기여를 보존한다.
- 경력기술서 초안을 우선 완성하고 확인 사항은 별도로 전달한다.
- 업무의 필요성, 방법·순서·기준을 택한 이유, 본인 행동, 결과의 의미를 근거로 연결한다. 개인의 선택 이유는 직무 조사로 대신 만들지 않는다.

실제 후보자의 지원서 작성이나 자동 제출, 채용 결과 예측은 이번 배포 범위에 포함하지 않는다.

## 설계 선택

1. **단일 스킬과 필요한 참조자료**를 선택했다. 연구·작성·검토를 별도 스킬로 분산하지 않아 요건과 경력의 연결을 유지한다.
2. **고정 서식보다 조건에 따른 구성**을 선택했다. 지정 양식이 우선이며 자유 양식은 참고 구조를 제공한다.
3. **실행 코드 없는 초기 버전**을 선택했다. 일반적인 도구로 가능한 날짜·비율 계산을 별도 프로그램으로 복제하지 않는다.
4. **한국어 편집 스킬과 함께 사용**하도록 했다. 한국어 문법 규칙을 복제하지 않으며 최소한의 독립 실행 지침도 제공한다.
5. **공개 출처의 링크·자체 요약과 합성 사례**만 저장한다. 실제 후보자 자료는 재사용 스킬에 넣지 않는다.
6. **책임 분류와 기능별 작성 가이드를 구분**한다. 포함·제외 조건으로 먼저 분류하고 필요한 F코드의 질문·지표만 읽는다. 공통 수치·권한 규칙은 하나로 유지한다.
7. **정보 부족·범위 밖을 숨기지 않는다.** 대표 기능이 불명확한 복합 직무는 책임별 배정을 유지하며 대표 코드만 확인 전으로 둔다. 분류한 기능의 범위와 실제 채용 사례로 조사한 범위를 구분한다.
8. **직무의 연구 부족과 후보자 사실의 부족을 구분**한다. 전자는 작성자가 조사해 해소하고, 후자는 자료·진술을 확인한다. 직무 조사는 실제 지원 공고가 없거나 새 전문 분야를 받았을 때도 실행한다.
9. **‘왜?’를 내용 검수에 포함**한다. 근거 없는 동기·위기를 추가하지 않으면서 필요성·선택 기준·결과의 사용처가 읽히도록 연결한다. 문장마다 고정 틀을 반복하지 않는다.
10. **한국 기업의 공고와 현업자 작성 경험을 구분**한다. 공고의 팀 단계·책임·제출 요구는 해당 회사의 조건으로 기록한다. 과거 기술블로그의 개인 작성 경험은 서술 참고로 쓰며 현재 채용 정책이나 합격 효과로 바꾸지 않는다.

이 선택은 사용자의 요청 범위를 실행하기 위한 작성자의 판단이다. 특정 기관이 채택하거나 검증한 표준이 아니다.

## 완료 기준

- 출처별 원문·날짜·확인 범위와 적용 한계가 기록되어 있다.
- 유효한 SKILL.md, UI 메타데이터, 필요한 참조자료와 문서 구성안이 있다.
- 경력 중복, 권한 과장, 팀 지표, 예상 효과, 지정 양식 조건을 합성 입력으로 점검한다.
- 확장한 직무에서 계약·매출·수금, 공정 범위, 예산·실적, 수치 없는 운영 개선 등 변경된 동작을 독립 적용한다.
- 경계 사례·복합 책임·정보 부족·범위 밖을 적용하고, 동일 성과의 중복 합산과 분류 코드의 제출본 유출을 점검한다.
- 새로 보강한 13개 역할의 원문·날짜·열람 범위와 직무별 작성 질문을 기록한다.
- 추가 자료집에 있는 직무와 없는 직무에 각각 적용하고, 실제 조사 실행과 선택 이유·성과의 사실 보존을 확인한다.
- 한국 테크 기업 사례의 정확한 역할·국내 소속·날짜·열람 범위와 작성 질문을 연결한다. 기업별 제출 조건과 실제 인사관리 범위를 합성 경력 작성에 적용한다.
- 구조 검증과 상대 링크 확인을 통과한다.
- 개인 스킬 설치 결과를 원격에서 확인한다.
- 저장소 커밋과 게시 여부를 각각 검증한다.

## 검증의 한계

소수의 합성 사례 적용은 해당 입력에서의 동작 확인이다. 채용 성과, 모든 문서 형식, 특정 ATS 또는 실제 후보자의 사실관계를 검증하지 않는다. 평가 기록에 실행하지 않은 검사를 성공으로 적지 않는다.

분류 규칙은 명시된 범위에서 입력 책임을 중복 없이 배정하고 누락을 드러내기 위한 설계다. 모든 산업의 모든 직업에 대한 수학적 완전성·공식 직업분류 인증을 주장하지 않는다. 기존 A~G 실행은 당시 버전의 기록으로 보존한다.
