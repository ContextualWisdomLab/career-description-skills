# Career Description Skills

공개 채용 공고와 공식 직무·작성 자료를 조사해 한국어 팀장급 경력기술서를 작성·검토하는 스킬이다. **직접 책임지는 산출물을 기준으로 직무의 책임을 12개 기능에 분류**하고, **왜 그 일이 필요했고, 왜 그 판단을 했으며, 결과가 왜 의미 있는지**를 확인된 경력으로 설명한다.

## 포함된 스킬

[write-career-description](skills/write-career-description/SKILL.md)는 지원 요건에 맞는 과제와 정기 운영 경험을 골라 실제 책임·판단·행동·성과를 설명한다. 관리자뿐 아니라 전문 분야의 업무를 이끄는 리드나 팀장 승진 지원자의 경험도 실제 권한 범위 안에서 작성한다. 결산·영업 실적 관리·채용 운영·생산라인 관리도 해당 업무의 단위와 기간에 맞춰 설명한다.

```text
$write-career-description 스킬로 이 채용 공고와 경력 자료를 대조해
팀장급 경력기술서를 작성해 줘. 회사 지정 양식을 지키고,
직무에 맞는 성과 지표와 본인 역할·의사결정·팀 성과가 드러나게 써 줘.
새로운 직무는 해당 직무를 조사하고, 필요성과 선택 이유를 근거로 연결해 줘.
```

## 책임 기준 직무 분류

주분류는 **직접 책임지는 산출물의 목적과 대상**을 기준으로 정한다. 산업, 기술·AI·AX, 기획·운영 단계, 사람관리 여부는 별도 속성으로 기록한다. 여러 기능의 책임을 맡는 직책은 책임 단위로 나누고, 각 단위에 주분류 하나를 부여한다. 대표 기능은 주된 책무가 확인될 때만 정한다.

| 코드·기능 | 직접 책임지는 결과의 예 |
| --- | --- |
| F01 사업경영·전략 | 사업 방향·포트폴리오·자원 우선순위·통합 실행 |
| F02 제품·서비스·연구개발 | 제공 가치·제품 사양·UX·새 지식·기술·제품 기능 |
| F03 마케팅·커뮤니케이션 | 시장 인식·수요·브랜드·캠페인·대외 소통 |
| F04 영업·거래개발 | 판매·제휴·갱신의 거래조건과 계약 성사 |
| F05 고객지원·활용 | 이미 제공한 제품·서비스의 도입·사용·고객 문제 해결 |
| F06 구매·공급망·물류 | 외부 자원 조달·수급·재고·운송·배송 |
| F07 생산·시공·서비스 제공 | 재화 생산·시공·진료·교육 등 현장·전문 서비스 이행 |
| F08 인사·조직역량 | 고용·평가·보상·조직·사내 역량 체계 |
| F09 재무·회계·자본 | 결산·예산·전망·자금·자본·재무 보고 |
| F10 정보시스템·데이터 서비스 | 공통 디지털 업무기반·데이터 서비스의 공급·성능·가용성 |
| F11 시설·자산·행정지원 | 자기 조직의 물리적 업무기반·시설·자산·공용 사무 |
| F12 법무·위험·보증 | 법적 판단·준법·위험·보호 통제·적합성 판정·독립 검증 |

각 기능에 포함하거나 제외하는 조건과 경계를 판단하는 기준은 [책임 기준 직무 분류](skills/write-career-description/references/job-taxonomy.md)에 있다. 예를 들어 CRM 캠페인은 F03, CRM 시스템 기반은 F10이다. 고객의 제품 활용 지원은 F05, 갱신 계약 성사는 F04다. 규격품 생산은 F07, 별도 적합성 판정은 F12다. F10에도 개발이 있고 F02에도 출시 후 운영·개선이 있으므로, 개발/운영 단계만으로 기능을 배정하지 않는다.

MECE 원칙에 따라 **기업·기관의 사업 수행·조직 지원·보증 책임을 중복 없이 배정하고, 입력된 책임을 빠짐없이 점검**한다. 정보가 부족한 책임과 이 분류의 범위를 벗어난 책임은 그 상태를 따로 기록한다. 이들을 임의로 기타·운영·IT 직무에 넣지 않는다. 같은 프로젝트를 여러 책임으로 나누어도 동일한 성과를 다시 합산하지 않는다. 직함이나 분류 코드로 인사권을 추정하지 않는다.

## 신규 직무와 설명의 완성 기준

스킬에 없는 직무·전문 분야는 **그 직무 자체를 조사해 작성 기준을 보강**한다. 같은 기능에 속해도 간호·교육·시공·숙박의 책임과 성과 기준은 다르다. 직무명과 실제 책임을 확인하고, 공식 공고와 기관의 역할 자료에서 목적, 판단, 산출물, 권한, 성과 확인 기준을 찾는다. 낯선 직무명이라는 이유로 미확정 상태나 분류 범위 밖에 두지 않는다.

직무별 자료에는 식품 R&D, 간호, 교육, 시공, 시설, 총무, 법무, 산업안전, 환경, 객실 운영, 식음료, 농축산, 예방보존의 13개 사례가 있다. 자료에 없는 다른 직무도 같은 조사 절차를 적용한다. 공고의 상태·직급·지역과 실제 읽은 범위는 각 사례에 기록했다.

핵심 경력은 **필요성·맥락 → 선택 기준과 본인 행동 → 확인된 결과와 의미**를 연결해 쓴다. 독자가 ‘왜?’라고 물을 부분을 점검하고, 후보자의 기존 자료와 진술에서 답을 찾는다. 외부 직무 자료는 확인할 질문을 정하는 근거로 쓰며, 후보자가 실제로 선택한 이유를 대신하지 않는다. 후보자에 관한 사실이 빠져 있으면 해당 사실을 확인하되, 작성 가능한 본문은 먼저 완성한다.

## 한국 테크 기업 사례

[한국 테크 기업 자료](skills/write-career-description/references/korean-tech-cases.md)에 공식 공고 6건을 추가했다. 당근 광고 제품 PM, 쿠팡 백엔드 엔지니어링 매니저, 채널톡 엔터프라이즈 영업·CX 리더, 토스뱅크 채용 리더, 리디 재무 팀장이다. 각 역할의 책임을 제품·개발, 영업, 고객 활용, 인사, 재무 기능에 연결하며 기업군을 별도 직무로 추가하지 않는다.

팀장·리더 역할 5건과 프로젝트 리딩을 포함한 제품 전문 역할 1건을 구분한다. 각 사례에는 목적·판단·권한·제출 조건과 함께 ‘왜 그 선택을 했고 결과가 무엇을 바꿨는가’를 확인할 질문을 담았다. 이 질문은 경력기술서 작성을 돕기 위한 제안이며, 회사가 지정한 면접 문항은 아니다. 우아한형제들 기술블로그의 2017년 개인 작성 경험은 별도 참고 자료로 두고 채용 공고 수에 포함하지 않는다.

## 사용

Agent Skills를 지원하는 환경의 개인 스킬 경로에 `skills/write-career-description` 폴더 전체를 설치한다. `SKILL.md`와 참조자료를 함께 유지한다. 설치 경로와 활성화 방식은 사용하는 클라이언트의 지침을 따른다. ChatGPT 개인 스킬은 해당 환경의 skill-creator 절차로 설치한다.

기본 입력은 목표 공고, 경력 자료, 제출 양식이다. 공고가 없으면 목표 역할을 기준으로 범용 초안을 만들 수 있다. 문서 파일을 요청받으면 해당 환경의 DOCX/PDF 생성 도구를 함께 사용한다.

한국어는 [ContextualWisdomLab/korean-writing-skills](https://github.com/ContextualWisdomLab/korean-writing-skills)의 korean-editing을 적용해 편집한다. 설치본이 없으면 공식 저장소의 지침을 읽고 적용한다. 외부 스킬의 설치나 실행 코드의 다운로드·실행은 자동으로 수행하지 않는다.

## 근거 범위

조사 기준일은 **2026-11-08, Asia/Seoul**이다. 공개 채용 공고는 요구사항을 보여 주는 사례다. 실제 합격자의 경력기술서, 채용 성공률 또는 특정 형식의 효과를 입증하는 자료로 취급하지 않는다. 상세 열람 범위와 날짜는 채용 조사 파일에 기록했다. 마감된 공고, 해외 사례, 과거 직무자료, 인사관리 책임이 확인되지 않은 전문 역할은 각각 구분한다. 목록에 없는 직무·전문 분야를 받으면 그 요청에서 자료를 추가 조사해 작성 기준에 반영한다.

12개 기능은 경력기술서 작성을 위한 자체 분류다. ILO의 실제 과업·책무에 관한 개념을 참고했으며, ISCO·NCS 코드를 복제했거나 공식 인증을 받은 분류는 아니다. 실제 조직의 모든 직책이 한 기능에만 속하거나 확인하지 못한 책임까지 자동으로 판정할 수 있다고 주장하지 않는다.

경력 기간의 중복 제거, 역할 구분, 내부 근거표와 문서 구성은 이 저장소에서 정한 편집·검증 방식이다. 이를 모든 회사의 의무 기준으로 확대하지 않는다. 고정된 쪽수·ATS 점수·합격률을 보장하지 않는다.

## 후보자 자료

예시와 평가 입력은 모두 합성 자료다. 실제 이력서, 연락처, 보상, 비공개 프로젝트·고객 자료를 이 저장소에 추가하지 않는다. 문서 작성은 지원서 전송이나 포트폴리오 공개를 포함하지 않는다.
