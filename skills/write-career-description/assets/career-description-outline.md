# 경력기술서 구성

이 파일은 작성자가 참고하는 구성안이다. 제출본을 완성할 때는 아래의 작성 안내, 안내용 괄호, 비어 있는 항목을 제거한다. 제출처의 지정 양식이 있으면 그 양식이 우선한다.

## 1. 경력 요약

전문 영역, 실제 경력 기간, 대표적인 책임과 확인된 강점을 3~5문장으로 연결해 쓴다. 이 분량은 작성을 시작할 때 참고하는 기준이며 필수 규격은 아니다. 지원하려는 직함을 현재 직함으로 쓰지 않는다.

사용자가 포부·기여 방향을 요구하거나 문항이 이를 묻는 경우, 확인된 경험을 지원 직무의 구체적인 과제와 앞으로 맡을 행동으로 연결한다. 자유 양식에서는 요약 끝에 짧게 덧붙일 수 있고, 지정 문항이 있으면 그 위치에 쓴다. 과거 업무·성과만 허용하는 양식이나 요청하지 않은 경력기술서에는 자동으로 추가하지 않는다.

**합성 예문:** 현업 인터뷰와 검수 기준 작성 경험이 있고, 지원자는 고객지원 지식관리 직무에서 상담팀과 개발팀의 협업을 이끌고 싶다고 밝혔다. “현업의 요구를 검수 기준으로 구체화한 경험을 바탕으로, 상담팀과 개발팀이 함께 지식관리 체계를 개선하도록 이끌겠습니다. 이용과 피드백을 확인하며 다음 개선 과제를 정하겠습니다.”

미래의 행동을 밝힌 문장이다. 과거에 시스템을 직접 구현한 성과로 바꾸거나, 자료에 없는 개선율·시한·채용·평가 권한을 넣지 않는다. 지원자가 밝힌 목표는 미래 목표로 유지한다. 포부는 요약이나 허용된 별도 항목에 두고 회사별 과거 실적 안에는 섞지 않는다. 이력서·자기소개서와 함께 작성할 때 기여 방향은 맞추되, 경력기술서에서는 뒷받침하는 경험과 적용 방법을 중심으로 쓰고 같은 문단을 복사하지 않는다.

## 2. 회사별 경력

회사명 / 재직 기간 / 공식 직함을 표시하고 조직 내 역할과 책임을 간결히 적는다. 최근 경력부터 일관되게 배치한다. 자문·겸직은 다른 업무와 병행했는지 자료에 나온 대로 적는다. 초기 경력도 지원 요건이나 전문성을 뒷받침하면 남긴다.

## 3. 주요 경험과 성과

지원 요건과 가장 관련이 깊은 경험부터 고른다. 각 사례에는 다음 정보를 필요한 만큼 담는다.

- 프로젝트·과제 또는 정기 운영 업무와 기간
- **프로젝트별 필수 확인: 목적·해결할 문제.** 누구의 어떤 문제·요구를 해결하려 했는지 원자료·승인된 과제 제안서·요구사항·운영 계획·사용자 진술에서 확인한다. 프로젝트명·사용 기술·산출물만으로 목적을 추정하지 않는다.
- 본인 역할, 팀·협업 범위, 의사결정권
- 핵심 판단과 행동, 당시 제약·대안·선택 기준
- 확인된 결과·산출물, 측정 기간·범위, 실제 활용과 운영 변화의 의미

하나의 경험은 이 절과 회사별 경력의 하위 항목 중 한 곳에서만 자세히 설명한다. 결산, 분기 영업, 채용 운영, 생산라인 관리처럼 반복되는 업무는 운영 대상·기간·관리 기준·개선 결과를 중심으로 쓴다. 모든 경험을 출시·개발 프로젝트로 바꾸지 않는다. 경험이 적으면 별도 성과 절을 늘리지 않아도 된다. 형식을 채우려고 확인되지 않은 배경이나 성과를 만들지 않는다.

본문에 남긴 각 프로젝트는 확인된 목적을 짧게 밝힌 뒤 개인 역할·판단·행동과 확인된 산출물·효과로 연결한다. 자유 양식의 상세 설명에서는 첫 문장이나 도입절에 목적을 두고, 짧은 이력서 항목에서는 한 구절로 압축한다. 지정 양식은 기존 항목과 순서를 유지한다. 목적이 이미 분명하면 별도 목적 항목이나 같은 문장을 중복 추가하지 않는다.

목적은 기대한 변화이며 실제 달성 여부는 별도 근거로 판단한다. 프로젝트의 목적, 특정 방법을 선택한 이유, 개인 역할, 결과를 서로 대신 쓰지 않는다. 목적이 자료에 없으면 원자료를 먼저 찾고, 남은 질문만 문서 밖에 둔 채 확인된 행동·산출물을 작성한다. 공고의 일반 목적이나 기술의 통상적인 장점을 가져와 빈칸을 채우지 않는다.

## 4. 직무 전문성·도구·자격·학력

요청받았거나 직무 적합성을 판단하는 데 필요한 항목을 정확한 명칭·상태·시점으로 제시한다. 전문 방법과 도구는 실제 적용 경험과 연결한다. 직무상 필요한 자격·면허는 실제로 취득했고 유효한 상태인지 확인하며, 교육 이수로 대체하지 않는다. 자기소개서·이직 사유·입사 후 계획은 요청받은 경우 해당 문항에 따로 쓴다.

## 별도 사용자 검토 메모

제출용 본문 밖에 지원 요건과 경력의 차이, 상충하는 사실, 수행하지 못한 파일 검증을 짧게 적는다. 모든 경력에 확인 표지를 붙이거나 일반적인 주의사항을 길게 나열하지 않는다.
