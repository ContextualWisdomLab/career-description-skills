## 1. 조사로 해결할 빈칸과 후보자에게 확인할 사실

스킬에 없는 직무·전문 분야·새 명칭을 접했다는 이유로 해당 직무를 미확정 상태로 두거나 범위 밖으로 분류하지 말라. 그 직무 자체를 조사하여 목적·책임·판단·산출물·평가 기준을 확보하라. 기존 기능에 포함된 세부 직무에도 같은 원칙을 적용하라. F코드가 같다는 사실만으로 다른 직무의 질문과 지표를 그대로 쓰지 말라.

다음 세 종류의 빈칸을 구분하라.

| 빈칸 | 해결 방법 |
| --- | --- |
| 직무 지식·해당 분야 사례가 없음 | 작성자가 공식 직무·채용·전문기관 자료를 조사하고 역할 설명과 작성 기준을 보강 |
| 후보자의 실제 역할·선택 이유·성과가 없음 | 기존 경력 자료·의사결정 기록·사용자 진술을 확인하고 필요한 구체적 질문을 전달 |
| 모집 상태·직속 인원·정확한 게시일 등 원문 미표시 | 확인 가능한 자료를 찾아 그 항목의 확인 범위만 기록. 이것을 직무 전체의 미확정 상태로 확대하지 않음 |

직무가 왜 존재하는지는 외부 자료로 이해할 수 있다. 후보자가 왜 그 방법을 선택했는지는 후보자에 관한 근거로 확인해야 한다. 채용 공고의 목적·요건을 개인의 동기·경험·실적으로 옮기지 말라.

## 2. 신규 직무 조사 절차

1. **업무를 특정하라.** 목표 직무명, 실제 책임, 산업·대상, 지역, 직급·권한을 분리하라. 동명의 다른 직무와 구별하고 국문·영문·통용 명칭으로 검색하라.
2. **해당 직무의 원문을 읽어라.** 실제 지원 공고와 기업 공식 채용사이트·공식 ATS·기관 직무기술서를 우선하라. 공고가 없으면 같은 책임을 맡는 역할 자료를 찾고, 전문기관·직업분류·직무 표준으로 의미를 보강하라. 국내 원문이 부족하면 해외·과거 사례의 적용 범위를 표시하라.
3. **접근 문제를 해결하라.** 빈 페이지나 제목만 읽히면 기업의 다른 공식 게시 경로, 역할명 변형, 기관 자료로 이어가라. 검색 요약을 상세 본문으로 취급하지 말고 리디렉션 후 직무명이 같은지 확인하라. 실제 접근 제한이 남으면 시도한 경로와 확인된 범위를 알려라. 조사하지 않은 상태를 완료로 보고하지 말라.
4. **역할 카드를 만들라.** 아래 표의 항목을 기록할 때는 원문에서 확인한 사실과 편집자가 적용을 위해 내린 판단을 구분하라. 해당 직무의 목적·책임·주요 판단·산출물·권한·성과 확인 기준을 설명할 근거가 갖춰질 때까지 보완하라. 출처 수만 채우지 말고, 의미가 상충하거나 중요한 경계가 남으면 다른 공식 출처와 대조하라.
5. **분류와 작성 가이드를 보강하라.** 조사에서 확인한 산출물을 기준으로 [책임 분류](job-taxonomy.md)를 적용하라. 기존 정의에 실제 조직 업무가 들어가지 않으면 그 책임에 맞는 정의·포함·제외 조건을 보완하고 인접 기능과 중복을 검토하라. 새 직무명을 이유로 코드를 늘리거나 ‘기타’로 몰지 말라.
6. **후보자 경험을 연결하라.** 역할 카드에서 지원 요건·판단 질문을 뽑고 후보자 근거와 대조하라. 반복 운영, 전문 서비스, 연구, 관리 업무를 각각의 실제 산출물로 설명하라.
7. **재사용 근거를 남겨라.** 이번처럼 스킬 수정이 요청된 작업에서는 공식 URL·확인일·요약·경계·작성 질문을 저장소에 반영하라. 일반적인 경력 작성에서는 작업용 조사표에 남기고, 별도 승인 없이 스킬·공개 저장소에 후보자 자료를 추가하지 말라.

| 역할 카드 항목 | 기록할 내용 |
| --- | --- |
| 출처와 시점 | 회사·기관, 정확한 직무명, URL, 확인일, 게시·마감일 표시, 현재/마감/역할 정의 구분, 읽은 본문·첨부 범위 |
| 존재 목적 | 누구의 어떤 문제·수요·위험을 다루는 역할인지 |
| 책임과 산출물 | 업무 대상, 직접 결과물, 완료·인도·검수 기준 |
| 판단 | 비교하는 대안, 제약·우선순위·상충 조건, 의사결정 대상 |
| 권한과 협업 | 직접관리·전문 판단·조율·승인의 확인 범위 |
| 성과 확인 | 그 직무가 쓰는 지표·문서·관찰, 대상·분모·기간·조건 |
| 작성 적용 | 후보자에게 확인할 이유·행동·근거 질문, 인접 기능 경계 |

[추가 직무 조사](expanded-role-research.md)는 출발점이다. 자료에 없는 직무를 새로 받으면 이 절차를 실행하라.

### 외부 독자가 모를 개념 조사와 설명

약어를 풀어 쓰는 것만으로 이해가 해결되는지 판단한다. 회사 내부의 프로젝트·조직·제도 이름, 업계별 약어, 생소한 기술·방법·지표가 핵심 경험을 이해하는 데 필요하면 **작성 전에 의미·목적·기능을 조사하고 확인한다.** 작성자가 익숙하다는 이유로 외부 독자도 안다고 가정하지 않는다.

1. **독자와 필요한 설명을 정한다.** 채용담당자·다른 직군의 임원·해당 분야 전문가 중 누가 읽는지 살핀다. 이름만으로 무엇을 하는 활동·제품·시스템인지 알기 어려운 핵심 개념을 고른다. 원문에 이미 충분한 설명이 있거나 전문 독자에게 통용되는 용어는 기초 설명을 반복하지 않는다. 맞춤법만 요청한 작업에서는 설명을 임의로 늘리지 않고 필요한 보완을 별도로 제안한다.
2. **근거에 따라 조사한다.** 사용자가 준 정의·공식 링크와 승인된 자료를 먼저 읽는다. 공개 개념은 해당 기업·제품·표준기관의 공식 원문에서 뜻과 쓰임을 확인한다. 동명 개념의 회사·분야·시점·버전을 대조하고, 검색 요약을 본문 확인으로 표시하지 않는다. 이미 충분히 확인한 정의를 다시 검색하기 위한 검색은 하지 않는다.
3. **비공개 표현을 보호한다.** 공개 여부를 확인하지 못한 사내 명칭·내부 URL·고객명·화면·문서 내용을 외부 검색어나 업로드에 넣지 않는다. 승인된 내부 자료와 사용자 설명으로 의미를 확인하고, 제출에는 공개가 허용된 기능·목적만 쓴다. 자료를 읽을 수 있다는 사실을 외부 공개 허가로 취급하지 않는다.
4. **개념과 개인 경력을 구분한다.** 확인한 뜻, 업무상 목적·기능, 출처·확인일·열람 범위를 작업 노트에 짧게 기록한다. 공식 자료에 적힌 기업 전체의 추진 목적·활동·성과는 개념 설명에만 쓴다. 그것을 후보자의 담당 범위·개발 실적·달성 성과로 옮기지 않는다. 활동 자체와 이를 지원하는 시스템도 구별한다.
5. **본문에는 이해에 필요한 만큼 쓴다.** 첫 등장에 ‘무엇을 위한 어떤 활동·기능인지’를 평이하게 밝히고 필요한 정식 명칭을 함께 둔다. 영어 원어만 나열하거나 낯선 약어를 다른 약어로 설명하지 않는다. 설명 뒤에 후보자가 실제로 맡은 판단·행동을 잇고, 반복 등장에서는 짧게 쓴다. 정확한 기술명·지표·자격명은 보존한다.
6. **모르는 뜻을 만들지 않는다.** 약어의 원어·기능을 추측하거나 동명의 공개 제품으로 단정하지 않는다. 확인 가능한 일반 설명만으로 뜻을 보존할 수 있으면 그 범위에서 작성한다. 핵심 의미나 공개 범위가 남으면 원자료 또는 사용자에게 그 사실만 확인하고 다른 항목은 계속 작성한다. 제출 본문을 추측이나 작업용 질문으로 채우지 않는다.

**공개 개념의 예.** 효성의 [C-Cube 공식 소개](https://blog.hyosung.com/4960)는 고객·최종 고객·경쟁사 의견을 사업 전략과 실행에 연결하는 고객 중심 경영 활동을 설명한다. 외부 독자에게는 ‘고객 의견을 사업 실행과 결과 관리로 이어가는 고객 중심 경영 활동(C-Cube)’처럼 목적을 먼저 설명할 수 있다. 관련 시스템의 요구사항·검수를 맡았다는 사실만 있으면 그 역할만 연결한다. 이를 프로그램 창설이나 전사 성과로 확대하지 않는다. 출처는 2020-10-13 게시물이며, 2026-11-08에 본문을 확인했다. 당시 소개이며 현재 운영 상태나 후보자의 참여를 증명하지 않는다.

**합성 예문.** 공개할 수 없는 프로젝트명 대신 승인된 기능으로 쓴다. 자료가 ‘부서별 장비 요청과 처리 상태를 확인하는 사내 도구, 본인은 요청 화면·검수 기준 정의’라면 ‘부서별 장비 요청과 처리 상태를 확인하는 사내 도구의 요청 화면과 검수 기준을 정의했습니다’로 쓴다. 비용 절감이나 처리시간 개선을 추가하지 않는다.

마지막으로 프로젝트명·약어를 가려도 외부 독자가 업무 목적과 본인 역할을 이해할 수 있는지 확인한다. 이 절차는 독자 이해와 사실 보존을 위한 편집 기준이며, 모든 독자에게 같은 수준의 기초 설명을 요구하지 않는다.

## 3. 독자의 ‘왜?’에 답하는 근거

핵심 사례를 읽은 독자가 아래 질문에 답할 수 있게 하라. 답은 본문에 자연스럽게 연결하고 문항·표지를 제출본에 노출하지 말라.

| 독자의 질문 | 연결할 근거 | 피해야 할 비약 |
| --- | --- | --- |
| 왜 이 일이 필요했나? | 실제 관찰, 고객·현장 요구, 업무 공백, 손실·위험·제약 | 자료 없는 위기·매출 손실·경쟁 환경 만들기 |
| 왜 그 판단·방법·순서를 택했나? | 당시 대안, 선택 기준, 비교·시험·협의 결과, 적용 조건 | 사용한 도구 이름만으로 우월성을 주장하거나 선택 이유를 대신 만들기 |
| 왜 본인의 경험으로 평가할 수 있나? | 본인이 결정·설계·실행·조율한 부분과 다른 담당자의 역할 | 팀 전체 결과를 개인 독점 성과로 바꾸기 |
| 왜 그 결과가 의미 있나? | 기준값·대상·기간과 확인된 사용·운영·고객 변화 | 산출물을 효과로, 상관을 원인으로, 목표를 실적으로 바꾸기 |

모든 문장에 네 답을 반복하지 말라. 사례 전체에서 필요한 연결이 드러나면 충분하다. 짧은 요약에는 핵심 결과와 판단을 남기고 상세 사례에서 맥락을 보강하라. 직무를 모르는 독자도 대상·문제·행동·결과를 따라갈 수 있도록 약어와 전문 용어의 의미를 필요한 만큼 설명하라.

선택 이유가 자료에 없으면 이미 제공된 문서에서 먼저 찾아라. 그래도 없으면 ‘당시 어떤 조건 때문에 A를 선택했는가?’처럼 빠진 연결에 대한 질문을 따로 적고, 확인된 사실로 완성할 수 있는 본문은 먼저 작성하라. 그럴듯한 경영 논리를 넣어 빈칸을 숨기지 말라. 목적은 ‘~을 위해’, 관찰 결과는 ‘~으로 확인됐다’처럼 구별하되 인과가 입증된 경우에는 그 강도를 약화하지 말라.

## 4. 문장 구성과 합성 예시

기본 연결은 `필요한 이유와 맥락 → 선택 기준·본인 행동 → 확인된 결과와 의미`다. 제출 형식에 맞게 결과를 먼저 제시할 수 있다. 한 문장에 모두 압축해 읽기 어렵게 만들지 말라.

### 합성 예시: 총무의 장비 지급 개선

제공 사실: 입사자의 첫날 계정·장비 누락이 분기 40명 중 8명. 부서별 요청 시점이 달랐음. 전사 시스템 교체는 다음 분기로 예정되어 있어 기존 신청서의 필수 항목·마감·담당자를 먼저 통일하기로 운영회의에서 합의. 본인은 요청 이력 분석과 양식·마감 기준 설계를 담당. 구매·보안팀의 장비·권한 승인 절차는 바꾸지 않음. 다음 분기 같은 기준 40명 중 누락 2명. 다른 변화의 영향은 분리하지 않음.

- 설명이 부족한 문장: ‘입사 지원 프로세스를 개선하고 누락을 줄였습니다.’
- 근거가 연결된 문장: ‘입사자 40명 중 8명에게 첫날 장비·계정 누락이 발생해 부서별 요청 이력을 분석했습니다. 다음 분기로 예정된 시스템 교체 전에도 적용할 수 있도록 신청서의 필수 항목·마감·담당자를 통일하는 안을 설계하고 운영회의 합의에 따라 적용했습니다. 구매·보안팀의 승인 절차는 그대로 유지했습니다. 적용 후 다음 분기에 같은 기준으로 확인한 결과, 장비·계정이 누락된 입사자는 40명 중 2명으로 줄었습니다.’

개선은 첫날 지원의 누락 지표로 설명했다. 후보자의 분석·설계, 다른 팀의 승인, 선택의 시간 제약을 연결했다. 온보딩 생산성·매출·이직률 개선이나 인과적 기여율은 만들지 않았다. 예시 수치는 실제 지원자에게 재사용하지 말라.

### 이유가 없는 입력

‘검토 시간을 줄이려고 자동화를 도입했고 30% 개선했다’만 있다면 어떤 검토인지, 원래 병목, 자동화를 택한 기준, 시간의 정의·표본·기간을 확인하라. 자동화를 택한 이유가 ‘인력 부족’이었다고 가정하거나 전사 생산성 30% 향상으로 바꾸지 말라.

## 5. 최종 확인

- 새 직무의 이름만 배정하지 않고 그 직무의 목적·책임·판단·산출물을 실제 출처에서 조사했는가?
- 출처·지역·시점·권한의 확인 수준을 구분했는가? 마감된 공고를 현재 모집으로 소개하지 않았는가?
- 핵심 사례에서 왜 필요했고, 왜 해당 판단을 했으며, 결과가 무엇을 바꿨는지 근거로 설명되는가?
- 설명 문장을 추가하며 없는 동기·위기·대안 비교·성과·권한을 만들지 않았는가?
- 공고의 요구, 후보자의 사실, 편집자의 추론이 구분되는가?
- 남은 질문은 실제 후보자 사실이나 접근 제한에 한정되는가? 단지 낯선 직무라는 이유로 조사를 미루지 않았는가?
