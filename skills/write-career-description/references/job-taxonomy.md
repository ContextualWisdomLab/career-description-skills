## 1. 적용 범위와 분류 단위

기업·기관의 팀장급 경력기술서에서 다루는 **사업 수행·조직 지원·보증 기능**을 분류하라. 주분류는 **직접 책임지는 산출물의 목적과 대상**을 기준으로 정하라. 직함, 산업, 기술, 경력 단계처럼 기준이 서로 다른 항목을 같은 목록에 놓지 말라.

직무명·사람·프로젝트 전체를 분류 단위로 삼지 말고, `책임 대상 + 본인의 판단·행동 + 직접 책임지는 산출물·결과`를 하나의 책임 단위로 삼아라. 독립적으로 검수할 수 있는 산출물이 둘이면 책임을 나누어라. 같은 결과를 설명하는 행동마다 단위를 잘게 쪼개지는 말라.

MECE는 이 범위에서 **같은 책임을 한 번 배정하고, 제공된 책임을 빠짐없이 점검하는 규칙**으로 적용하라. 모든 실제 직책이 한 기능만 가진다고 가정하거나, 12개 이름만으로 전 세계 모든 직업의 완전한 분류를 증명했다고 말하지 말라.

## 2. 배정 순서

처음 보는 직무·전문 분야는 [신규 직무 조사](research-and-reasoning.md)에 따라 목적·책임·판단·산출물을 조사하라. 스킬에 사례가 없다는 이유로 후보자의 정보가 부족하다거나 분류 범위를 벗어났다고 판단하지 말라. 조사 결과로 정의와 경계를 보강한 뒤, 확인된 책임을 각각 배정하라.

1. 공고·경력에서 책임 단위를 뽑고 ID를 부여하라. 직함과 원래 사실은 그대로 보존하라.
2. 각 단위의 산출물, 사용 대상, 완료·검수 기준, 제안·실행·승인 범위를 확인하라. 직속 인원과 최종 승인권은 분류 코드에서 추정하지 말라.
3. 아래 포함·제외 조건과 경계 규칙으로 **책임 단위마다 F01~F12 중 하나**를 배정하라. 전문 기능의 산출물이 확인되면 그 기능을 사용하라. `운영`, `기획`, `데이터`, `AI`라는 단어를 배정 근거로 삼지 말라.
4. 여러 코드가 동시에 맞으면 먼저 서로 다른 산출물이 섞였는지 확인하라. 분리할 근거가 없으면 가장 직접적인 책임 산출물과 검수 기준을 다시 확인하라. 직함·공유 KPI·소요시간의 임의 가중치로 동점을 해소하지 말라.
5. 직무 전체의 대표 기능은 공고나 사용자 자료에서 주된 책무가 확인될 때만 하나를 정하라. 동등한 복합 책무라면 각 책임을 분류하고 대표 기능은 확인 전으로 남겨라. 대표 기능이 미정이어도 작성 가능한 경력은 완성하라.
6. 산업·전문 분야·수행 방법·단계·리더십을 별도 속성으로 붙여라. 분류 코드는 작업용 근거표에 두고 제출용 경력기술서에 자동으로 노출하지 말라.

## 4. 경계 판정

| 경계 | 판정할 직접 산출물 |
| --- | --- |
| 사업전략 / FP&A | 사업·포트폴리오 선택과 실행 우선순위는 F01, 재무모형·전망·보고는 F09. 같은 회의에 제출해도 산출물을 구분 |
| CRM / 영업 / 고객성공 | 캠페인·고객군 메시지는 F03, 거래조건·갱신 계약은 F04, 고객의 사용·성과 계획은 F05, CRM 시스템 기반은 F10 |
| 제품 / 마케팅 / 지원 | 제공 상품의 사양·UX는 F02, 상품을 알리고 선택하게 하는 콘텐츠는 F03, 이용 중 문제 해결은 F05 |
| 연구·개발 / 생산·서비스 | 새 지식·설계·제품 기능은 F02, 확정된 사양·절차에 따른 실제 생산·서비스 이행은 F07. 산업·소프트웨어 여부로 나누지 않음 |
| 제품 개발 / IT 기반 | 제공 가치·제품 사양·연구 결과는 F02, 공통 시스템·데이터 서비스의 공급·성능·가용성은 F10. F10에도 설계·개발이 있고 F02에도 출시 후 운영·개선이 있으므로 개발/운영 단계로 자동 분류하지 않음 |
| 공급망 / 생산 / 품질보증 | 수급·재고·이동은 F06, 공정에서 규격품을 생산하는 것은 F07, 별도로 적합성을 검증·판정하는 것은 F12 |
| 현업 품질·보안 / 별도 통제 | 자신의 산출물이 충족해야 할 품질·안전·보안 조건은 본래 기능, 법적 판단·위험 평가·보호·감시·통제 설계·적합성 판정 자체가 산출물이면 F12. 별도 부서 소속은 필수 조건이 아님 |
| 구매 / 자산 운영 / 고객 시공 | 발주·구매 조건은 F06, 자기 조직의 업무시설 구축·유지는 F11, 고객에게 계약된 공사를 인도하는 것은 F07 |
| 조직 역량 / 고객 교육 | 직원·관리자 역량·평가 제도는 F08, 독립된 교육과정의 제공은 F07, 이미 제공한 제품의 활용 교육은 F05. 유료/무료 여부로 판정하지 않으며 한 계약에 다른 산출물이 있으면 분리 |
| AI·AX / PMO / 운영 | 명칭을 지우고 실제 산출물을 판정. 전사 통합 변화는 F01, 현업 변화는 해당 기능, 공통 기술기반은 F10. 직함만 있으면 정보 부족 |

이 표는 조건을 확인하는 예시다. 명칭에 따른 일괄 매핑표로 사용하지 말라. 법무·감사·안전 등 전문 직무의 법적 자격과 국가별 권한은 해당 공고·자료에서 따로 확인하라.

## 5. 별도 속성

- **산업·현장:** 제조, 금융, 의료, 교육, 공공, 문화, 농림어업 등. 산업명이 기능 코드를 대신하지 않게 하라.
- **전문 분야·방법:** 디자인, 소프트웨어, 데이터, AI·AX, 법무, 품질, 보안 등. F12의 세부 분야도 전문 속성으로 기록하며, 서로 배타적인 별도 직무군이라고 주장하지 말라.
- **수행 단계:** 조사·기획·설계·구축·실행·운영·개선. 어느 단계인지와 어떤 기능인지 구별하라.
- **권한·리더십:** 사람관리, 전문 판단, 협업·과제 조율; 제안·실행·검토·승인 범위. `독립 감사`는 실제 독립성과 책무가 확인될 때만 기록하라.
- **조직·대상 범위:** 전사·사업·부서·팀·제품·라인, 직속·협업·외주 인원, 고객·지역. 범위가 크다고 상위 직함이나 인사권을 만들지 말라.

## 6. 누락·중복 점검

모든 입력 책임을 아래 세 상태 중 하나로 기록하라. 상태는 직무군이 아니다.

| 상태 | 처리 |
| --- | --- |
| 분류 완료 | 책임 단위에 주분류 1개, 실제 배정 근거와 관련 경력 근거 ID를 기록 |
| 정보 부족 | 직무 조사 후에도 후보자의 실제 대상·산출물·권한 등 배정에 필요한 사실이 부족한 경우. 부족한 사실과 질문을 남기며 임의 코드를 부여하지 않음 |
| 범위 밖 | 조직·사업·고객을 위한 활동과 무관한 사적 기록 등, 선언한 업무 책임 범위 자체에 속하지 않는 입력 |

처음 받은 책임 목록과 분리한 뒤의 최종 목록을 대조하라. 최종 책임 단위마다 위 상태 중 하나가 기록되어 있고, 분류를 마친 단위마다 코드가 하나씩 부여되어 있는지 확인하라. 보류했거나 범위를 벗어난 책임을 `기타`, `운영`, `IT`에 몰아넣어 완전성을 주장하지 말라. 해결하지 못한 항목이 있으면 무엇이 남았는지 함께 보고하라.

실제 기업·기관의 업무인데 현재 정의로 배정할 수 없으면 조사를 계속하고 정의를 보완하라. 새 직무의 이름만 보고 범위 밖으로 처리한 채 작업을 끝내지 말라. 공고에 게시일이나 인원수 일부가 표시되지 않았어도, 확인된 직무의 목적과 책무는 분류와 작성에 사용하라. 원문 접근 제한은 조사 상태로 기록하며, 새로운 직무군이나 후보자에 관한 사실로 취급하지 말라.

한 프로젝트가 여러 책임의 근거일 수 있다. 동일한 매출·절감·개선 결과에는 같은 근거 ID를 연결하고 **책임별로 다시 합산하지 말라**. 사례는 문서의 한 곳에서만 자세히 쓰고, 다른 기능에서는 필요한 기여만 연결하라. 분류에 필요하다는 이유로 자료에 없는 금액·기여율·기간·직속 인원을 만들지 말라.

조직의 수익·서비스 수행, 고객·시장, 공급·현장, 사람·돈·디지털·물리적 기반, 법적 의무·보증 책임을 점검하라. 의료·교육·문화·건설·농림어업 등에서도 같은 기준을 적용하되, 기능에 배정했다는 사실을 해당 분야의 채용 요건·자격·성과지표까지 검증했다는 뜻으로 쓰지 말라.

## 8. 분류 근거와 한계

**T01. ILOSTAT — International Standard Classification of Occupations (ISCO)**

- [공식 설명](https://ilostat.ilo.org/methods/concepts-and-definitions/classification-occupation/). 확인일: 2026-11-08. Definitions, Structure, History의 HTML 본문을 확인했다. 페이지의 정확한 게시·수정일은 확인하지 않았다.
- ILO는 한 사람이 수행하는 과업·책무를 job의 정의에 사용하고, 주요 과업·책무가 비슷한 job들을 occupation으로 묶는다. 숙련 수준과 전문화로 계층을 구성하며 직업과 산업은 구별되는 분류 대상이다.
- 이 자료에서 실제 과업·책무를 확인하는 원칙을 참고했다. **F01~F12, 책임 단위의 단일 배정, 경계표와 보류 절차는 이 스킬의 자체 설계**다. ISCO 코드·직급 체계·NCS 대응표 또는 공식 인증 분류가 아니다.

이 문서는 직무명 사전이나 통계적 직업 코딩 체계를 대체하지 않는다. 명시한 범위에서 입력된 책임을 중복 없이 배정했는지, 빠뜨린 책임은 없는지 검사하라. 실제 조직의 모든 기능을 12개 코드만으로 자동 판정할 수 있다고 보장하지 말라.
