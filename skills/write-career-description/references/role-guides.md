# 직무별 경력기술서 작성 가이드

공고의 책임과 지원자의 실제 경험을 기준으로 아래에서 필요한 절을 선택한다. 복합 역할은 주된 책임을 먼저 설명하고 보조 직무를 연결한다. 가령 영업 운영은 매출·영업 프로세스 책임인지, 물류 운영은 재고·납기 책임인지 구분한다. 직함의 `Manager`, `Lead`, `Head`는 사람관리 여부를 확정하지 않는다.

아래 질문·산출물·지표는 [채용 사례](hiring-research.md)를 참고한 **이 스킬의 편집 설계**다. 모든 공고의 필수 항목이나 공인 평가표가 아니며, 각 직무에 적힌 세부 전문 분야를 모두 조사했다는 뜻도 아니다. 없는 성과를 채우는 목록으로 사용하지 않는다. 숫자가 없으면 확인된 판단·기준·운영 변화·산출물로 완성한다. 날짜·권한·비율·귀속은 [공통 수치 규칙](evidence-and-metrics.md)을 함께 적용한다.

## 1. 사업·전략·경영기획

- **확인할 책임:** 사업 또는 시장의 범위, 전략 선택·우선순위, 사업계획·손익 책임, 투자안 제안과 승인, 여러 부서 실행을 연결한 범위.
- **경험과 근거:** 대안 비교와 선택 이유, 사업계획·경영 보고, 실행 과제와 점검 체계, 사업별 손익·운영 기록. 자료 작성과 최종 경영 의사결정을 구별한다.
- **지표를 쓸 때:** 매출·매출총이익·영업이익·현금흐름을 정확한 항목으로 표시하고 기간·사업 범위·실적/전망을 남긴다. 사업성 검토액·시장 규모·목표액을 실현 매출로 옮기지 않는다. 전사 결과를 단독 개인 성과로 쓰지 않는다.
- **정기 운영 표현:** 월별 실적 점검이나 연간 계획 수립을 운영 주기, 조정한 쟁점, 실제 의사결정·후속 실행으로 설명한다.

## 2. 영업·사업개발(BD)·제휴

- **확인할 책임:** 고객·산업·지역·채널, 신규/기존 고객, 협상과 계약 권한, 가격·할인 승인, 팀 목표와 구성원 코칭, 파트너의 역할.
- **경험과 근거:** 고객 세분화, 제안·협상 쟁점과 본인 행동, 영업기회 검토 기준, 계약·인식 매출·수금 기록, 파트너 운영·후속 매출.
- **지표를 쓸 때:** 미계약 파이프라인, 계약액, 매출 인식액, 수금액을 분리한다. 기간·통화·반복/일회 매출·취소 포함 여부를 확인한다. 수주율은 어떤 영업기회가 분모인지, 갱신율은 대상 고객·계약 기간이 무엇인지 확인한다. 매출총이익률과 영업이익률을 바꾸지 않으며 이익률 차이는 `%p`로 쓴다.
- **과장 방지:** 협약 체결을 매출 실현으로, 고객 접점을 계약 성사로, 가격안 제안을 최종 승인권으로 바꾸지 않는다. 공동 영업은 본인의 고객·협상·운영 기여를 명시한다.

## 3. 마케팅·브랜드·CRM

- **확인할 책임:** 고객군과 퍼널 단계, 브랜드/획득/유지 목표, 채널·예산 범위, 실험·소재·CRM 결정, 대행사와 내부 팀의 담당 범위.
- **경험과 근거:** 고객 조사, 타깃·메시지·채널 선택 이유, 캠페인·CRM 운영 기준, 실험 설계, 브랜드 조사·채널 성과 보고.
- **지표를 쓸 때:** 노출·도달·클릭·전환·유료 고객·매출을 같은 결과로 취급하지 않는다. GMV(거래총액)를 회사의 인식 매출·이익으로 바꾸지 않는다. ROAS는 어떤 귀속 매출과 광고비인지, CAC는 어떤 신규 고객과 획득 비용인지, 전환율은 분모·전환 사건·기간이 무엇인지 남긴다. 플랫폼 간 중복 전환·귀속 기간 차이를 확인한다.
- **과장 방지:** 광고 플랫폼이 귀속한 매출을 인과적으로 발생한 증분 매출로 단정하지 않는다. 비교집단 없는 전후 변화, 자연 유입, 가격·프로모션 변화를 구분한다. 브랜드 인지도·호감도는 조사 대상·표본·질문을 유지한다.

## 4. 제품·서비스기획·UX·디자인

- **확인할 책임:** 고객 문제, 제품·사용자·여정 범위, 로드맵·요구사항·우선순위 결정, 리서치·설계·검수·출시에서의 담당, 디자인 조직 운영 여부.
- **경험과 근거:** 사용자 조사와 문제 정의, 채택·기각한 대안, 우선순위의 이유, 요구사항·프로토타입·설계 기준, 출시 후 사용과 품질 변화.
- **지표를 쓸 때:** 출시 완료·사용·유지·수익을 구분한다. 활성·전환·유지율은 이벤트 정의·코호트·관찰 기간을 확인한다. UX 과제 성공률은 과제·참여자·실험 조건을 남긴다. 사용성 시험 결과를 전체 고객의 전환 개선으로 확대하지 않는다.
- **과장 방지:** PM/PO/Design Lead 직함을 직속 인원 관리로 추정하지 않는다. 연구·기획·디자인·개발의 기여와 최종 제품 결정권을 구분한다. 포트폴리오는 요청한 경우 공개 가능한 근거만 연결한다.

## 5. 인사·조직·채용·HRD

- **확인할 책임:** 대상 조직·직급·지역, 채용/평가/보상/조직문화/교육 영역, 제도 설계·운영·승인 권한, 현업 관리자와의 역할, HR팀 사람관리 여부.
- **경험과 근거:** 제도·평가 기준, 채용 계획과 단계별 개선, 관리자 지원, 온보딩·교육 설계, 실행 범위와 후속 활용. 제도 문서 작성, 승인, 시행, 정착을 구분한다.
- **지표를 쓸 때:** 채용 소요기간의 시작·종료 사건을 정의한다. 공석 승인부터 충원까지와 후보자 접촉부터 입사까지를 섞지 않는다. 입사자·오퍼 수락·충원 건수는 다른 지표다. 이직률은 자발/비자발·대상 인원·분모·기간을, 만족도는 응답자 수·응답률·척도를 남긴다.
- **과장 방지:** 교육 수료율을 업무 성과 향상으로, 만족도 변화를 인과적 유지율 개선으로 바꾸지 않는다. 참여 조직·교육 인원을 직속 인원으로 쓰지 않는다. 개인의 인사·보상·노무 사안을 재식별할 수 있는 정보는 경력 사례에 넣지 않는다.

## 6. 재무·회계·FP&A

- **확인할 책임:** 법인·사업·지역, 결산·예산·전망·자금·통제 범위, 회계 정책·검토·승인 단계, 감사 대응과 팀 운영에서의 실제 역할.
- **경험과 근거:** 월·분기 결산, 예실 분석과 경영 판단 지원, 전망 갱신, 자금 계획, 통제 기준·계정 정합성·감사 지적 후속 조치.
- **지표를 쓸 때:** 예산·전망·실적을 표시하고 같은 회계 정의·기간·범위로 비교한다. 예측 정확도는 예측 시점·대상·오차 산식이 있어야 한다. 결산 소요일은 마감 시작·완료 기준과 달력일/영업일을, 오류는 집계 기준·건수·금액을 확인한다.
- **과장 방지:** 현금 유입을 이익으로, 예산 감액을 실현 비용 절감으로, 일시적 운전자본 변화를 지속 성과로 바꾸지 않는다. 외부 감사 대응 경험을 감사의견 결정권이나 관련 자격 보유로 바꾸지 않는다. 수치가 없으면 정착한 통제·보고·검토 절차를 설명한다.

## 7. 구매·SCM·물류

- **확인할 책임:** 품목·공급사·지역, 구매·발주·운송·통관·보관·배송 범위, 계약·발주 승인, 공급 위험 대응, 파트너·인력 운영.
- **경험과 근거:** 공급사 선정·협상 기준, 재고·수요·발주 판단, 물류 구간 개선, 대체 공급·예외 처리, 파트너 성과와 표준 절차.
- **지표를 쓸 때:** 협상 단가 감소·비용 회피·실현 구매비 절감을 구분한다. 수량·사양·환율·운송 조건·비교 기준을 확인한다. 재고 회전·재고일수·결품·서비스 수준을 함께 보고, 납기·리드타임은 시작·종료·대상 구간을 명시한다. OTIF 등 사내 지표는 충족 조건을 확인한다.
- **과장 방지:** 재고 감소만으로 비용과 서비스가 함께 개선됐다고 단정하지 않는다. 공급사 작업자를 직속 구성원으로, 전체 공급망의 결과를 한 구간 담당자의 단독 성과로 쓰지 않는다.

## 8. 운영·CX·고객성공

- **확인할 책임:** 사업·고객군·채널·운영 시간, 현장·상담·BPO·파트너 범위, 품질·SLA·사고 대응, 고객 도입·활용·갱신에서의 책임.
- **경험과 근거:** SOP·상담/사고 처리 기준, 인력 배치·코칭, 고객 온보딩·활용 계획, 이슈 원인과 재발 방지, 파트너·부서 간 이관 개선.
- **지표를 쓸 때:** 첫 응답·해결 시간·처리량·재문의·재발·품질을 구분한다. CSAT/NPS는 응답자·응답률·기간을 유지한다. 갱신·해지·확장 매출은 고객 수/매출 기준, 대상 코호트, 계약·매출 인식 여부를 확인한다. P&L이 있으면 해당 사업 범위와 실제 책임을 명시한다.
- **과장 방지:** 상담 처리량 증가를 고객 경험 개선으로, 고객 성공 활동을 직접 수주로 자동 변환하지 않는다. 서비스 유지·사고 예방도 확인된 운영 기록과 범위로 설명할 수 있다.

## 9. 생산·제조·품질

- **확인할 책임:** 공장·라인·공정·제품군·교대, 생산계획·현장 인력·품질·안전·설비의 담당, 변경·출하 승인, 공급사와의 책임 경계.
- **경험과 근거:** 공정 조건 판단, 작업표준·검사·교육, 원인 분석·시정조치와 재발 확인, 현장 운영·인력 배치, 생산계획과 납기 관리.
- **지표를 쓸 때:** 불량률은 불량품 수/검사 수인지 결함 건수 기준인지 확인한다. 수율·초도합격률·폐기·재작업을 구분한다. OEE는 사업장 산식·가동 조건을, 생산성은 생산량과 투입 시간·인원을 확인한다. 제품 믹스·물량·교대·설비·공급사 변화가 동반됐는지 살핀다.
- **과장 방지:** 한 라인 시험을 공장 전체 성과로 확대하지 않는다. `%`와 `%p`, 관측 기간과 연간 예상치를 구별한다. 무사고 기간을 위험 제거의 증명으로 바꾸지 않는다. TFT·작업자 교육 인원을 관리 인원으로 추정하지 않는다. 품질 프로젝트 책임자는 인사관리자가 아닐 수 있다.

## 10. IT·개발·데이터·AI·AX·보안

- **확인할 책임:** 서비스·플랫폼·데이터·업무 범위, 기술 방향·설계·운영·품질·위험 판단, 현업과 개발팀의 역할, 채용·성장 지원 여부.
- **경험과 근거:** 설계 대안과 선택, 검토·개발·자동화·장애 대응, 데이터 품질·보안 통제, AI/AX의 업무 분석·예외 처리·검수·현업 정착.
- **지표를 쓸 때:** 처리시간·배포 간격·빈도·장애·품질·비용을 같은 생산성 지표로 바꾸지 않는다. 평균/중앙값·표본·기간·서비스 범위를 보존한다. 모델 오프라인 지표와 실제 현업 결과, 파일럿 사용과 정식 도입을 구분한다.
- **과장 방지:** 도구 도입을 조직 성과로 단정하지 않는다. Tech Lead와 사람관리자를 구분하고, 본인의 설계·검토와 다른 구성원의 구현을 분리한다. 예상 인건비 절감을 실제 비용 감소나 채용 대체로 쓰지 않는다.

## 자료가 부족할 때

작성을 진행하되 중요한 주장에 필요한 정보만 후속 질문으로 남긴다. 공통적으로는 대상·기간·본인 행동·결정권·결과의 근거를 확인하고, 각 직무에서는 가장 관련된 지표의 정의나 비교 조건을 묻는다. 위 목록 전체를 장문의 설문으로 전달하지 않는다. 직무 요건의 빈칸을 채우려고 사용자가 제공하지 않은 경험을 만들어 내지 않는다.
