# 경력 근거와 수치 처리

아래는 채용 공고와 기관 작성 지침을 적용하기 위한 이 스킬의 편집·검증 규칙이다. 법적 경력 인정 기준이나 채용 합격 예측 모델이 아니다. 근거 출처와 적용 범위는 [채용 조사](hiring-research.md)에 있다.

## 리더십을 확인할 질문

| 영역 | 실제로 확인할 내용 | 경력기술서에 쓸 증거 |
| --- | --- | --- |
| 사람관리 | 직속 인원, 기간, 채용·배치·평가·코칭에서의 권한 | 조직·역할 변경, 온보딩, 피드백 주기, 역량 개발과 확인된 결과 |
| 기술 리딩 | 설계·검토·표준·품질 기준의 제안·결정·승인 범위 | 대안과 선택 이유, 설계 기록, 도입 범위, 운영 결과 |
| 실행·협업 | 목표·우선순위·일정·의존성·갈등을 조정한 범위 | 부서 간 합의, 의사결정 기록, 이관·검수·출시 결과 |
| 사업·운영 | 예산 제안과 승인 구분, 비용·매출·위험·품질의 책임 | 기준값·기간이 있는 지표, 실제 집행·정착·운영 기록 |
| AI·AX | 바꾼 업무, 현업 사용, 사람 검토·예외 처리, 도입 단계 | 업무 대기시간, 처리시간, 오류·재작업, 사용 범위, 품질·비용 변화 |

공고에서 요구하지 않는 영역을 모두 채우려고 하지 않는다. 기술 리드가 반드시 인사관리자이거나, 관리자만 리더십 경험을 가진 것은 아니다. 공식 직함과 프로젝트에서 맡은 책임을 함께 표현한다.

### 권한을 정확히 표현하기

- 8명 프로젝트의 참여자라면 `8명 참여 프로젝트에서 설계 검토 담당`으로 쓴다. 직속 보고 8명이라는 근거가 있을 때만 `8명 팀 관리`로 쓴다.
- 면접 참여와 최종 채용 결정, 예산안 작성과 집행 승인, 목표 제안과 목표 확정은 각각 다른 책임이다.
- 신입 온보딩은 구성원 지원 경험으로 남긴다. 이를 인사평가·승진·채용 책임으로 확장하지 않는다.
- 여러 조직의 합의를 이끌었다면 조율한 쟁점과 결정 범위를 쓴다. 협업 인원 전체를 관리 인원에 넣지 않는다.

## 사실의 확인 수준

작업용 근거표에서만 다음을 표시한다.

1. **자료 확인**: 문서·기록·데이터에서 해당 사실과 위치를 확인했다.
2. **사용자 진술**: 지원자가 명시한 사실이다. 독립 검증과 구별하되 통상적인 경력 작성에 사용할 수 있다.
3. **계산값**: 확인된 입력·기간·단위·산식으로 산출했다. 원자료의 주장 강도를 넘지 않는다.
4. **상충·미확보**: 유리한 수치를 골라 쓰지 않는다. 확인된 공통 범위로 서술하거나 해당 주장만 보류하고 질문한다.

출처에 내용이 없다는 것과 사실이 없다는 것을 구별한다. 근거가 부족한 경우에도 확인된 행동과 산출물은 문장으로 완성한다. 이 상태 분류나 내부 파일 경로를 제출본에 노출하지 않는다.

## 경력 기간

- 기준일을 고정한다. `현재`는 사용자 시간대의 기준일로 환산한다.
- 날짜를 알면 실제 날짜 구간을 사용한다. 월만 알면 시작월과 종료월을 포함한 월 구간을 합집합으로 계산하고, 일자 확인 전에는 월 기준 근사임을 사용자에게 알린다.
- 학교·연구·프리랜서·파트타임·재직의 종류를 보존한다. 공고에 인정 조건이 있으면 그 조건에 해당하는 경력을 별도로 계산한다. 임의의 상근 환산율을 만들지 않는다.
- 병행한 자문은 별도 경험으로 표시하고 같은 달을 두 번 세지 않는다. 경력 공백을 메우거나 프로젝트 기간을 재직 기간으로 대체하지 않는다.
- 예: 2020.01~2022.12와 2023.01~2024.12는 월 기준 60개월, 약 5년이다. 2021.04~2022.03 자문을 병행해도 합집합은 늘지 않는다. 겹치는 활동을 더해 경력을 늘리지 않는다.
- 채용처가 다른 계산 규칙을 명시하면 그 규칙을 적용하고 계산 근거를 별도 기록한다. 작성자가 채용처의 최종 인정 여부를 확정하지 않는다.

## 성과 수치

계산 전에 지표 정의, 전후 값, 단위, 분모·표본, 비교 기간, 적용 범위, 측정 방법을 대조한다. 도구로 계산해 산술 오류를 줄인다.

| 입력 | 허용되는 표현 | 피할 해석 |
| --- | --- | --- |
| 같은 범위의 배포 간격 중앙값 10일 → 7일 | 3일 감소, 30% 감소 | 생산성 30% 향상, 배포 빈도 30% 증가 |
| 오류율 8% → 5% | 3%p 감소, 상대적으로 37.5% 감소 | 3% 감소만 써서 의미를 모호하게 만듦 |
| 기준값 0 → 12건 | 12건 발생·증가 | 증가율 산출 |
| 월간 비용 1,000만 원 → 800만 원, 한 달 관측 | 해당 월 200만 원 감소 | 연간 2,400만 원 실현 절감 |
| 계산표의 예상 연간 절감액 | 전제와 함께 예상액·시나리오로 표현 | 실제 절감액으로 제시 |
| 파일럿 2개 부서에서 확인한 결과 | 2개 부서 파일럿 결과 | 전사 정착·모든 사용자의 성과 |

상대 감소율은 `(이전 값 - 이후 값) / 이전 값 × 100`이며 이전 값이 0이면 정의되지 않는다. 단위·지표 방향·기간이 다른 수치를 한 개선율로 묶지 않는다. 입력이 범위이면 유리한 끝값만 고르지 않는다.

팀 지표는 팀의 결과로 쓰고 본인의 결정·행동을 붙인다. 시간상 함께 일어났다는 사실만으로 인과나 개인 기여율을 만들지 않는다. 근거가 인과를 뒷받침하면 그 범위에서는 명확히 표현한다.

## 합성 예시: AX 경험을 과장 없이 쓰기

**제공 사실**: 가상의 지원자가 2개 부서 18명을 인터뷰하고 승인 대기 구간 4개를 정리했다. 예외 처리 기준을 설계하고 요구사항·검수 기준을 작성했으며, 개발팀이 시범 시스템을 구현했다. 처리시간의 전후 측정은 하지 않았다.

**완성 문장**: `2개 부서 18명의 업무를 조사해 승인 대기 구간 4개를 정리하고 예외 처리 기준을 설계했다. 개발팀의 시범 시스템 구현에 필요한 요구사항과 검수 기준을 담당했다.`

이 문장의 강점은 업무 분석과 판단 기준 설계다. 제공되지 않은 시간 절감·채용 대체 효과를 추가하지 않는다. 실제 측정 자료가 있다면 그 결과를 적극적으로 보완한다.
